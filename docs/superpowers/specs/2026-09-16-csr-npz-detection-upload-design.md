# 攻击检测兼容 CSR-NPZ 上传设计

## 目标

攻击检测页面同时支持两类 NPZ：

- 自包含完整图：包含 `x` 和 `edge_index`，无需干净参考图。
- SciPy CSR 邻接矩阵：只包含被扰动后的邻接关系，由用户选择对应的数据集档案，
  平台从该档案补充节点属性。

同时删除“节点属性类型”选项，并把页面中的“防御工具”改名为“鲁棒防御模型”。

## 页面设计

- 上传区先选择 Cora、CiteSeer、PubMed 或 PolBlogs，再选择图文件。
- 完整 `x + edge_index` NPZ、完整 PT 和只有邻接矩阵的 CSR-NPZ 都关联所选数据集。
- 同一批 CSR 文件共用一个数据集，
  不同数据集应分批上传。
- 删除“节点属性类型”选择框。属性处理统一使用检测器检查点保存的自动策略。
- 侧边栏和页面标题中的“防御工具”改为“鲁棒防御模型”，不改变其运行逻辑。

## 数据流程

1. 上传文件仍先保存到 `artifacts/uploads/`。
2. 根据必选的数据集读取该档案的 `clean.pt`，并把它作为可信属性来源传给图加载器。
4. 如果文件是 SciPy CSR-NPZ，使用上传邻接矩阵和可信档案的 `x` 组成完整输入图。
5. 检测器只对组合后的完整图执行现有共享 GCN 推理，不使用节点标签，也不重新训练。
6. 完整 NPZ 即使选择了数据集，仍保留文件自身的 `x`；数据集选择只提供来源标识和
   自动属性策略。

## 校验和错误处理

- CSR 邻接矩阵必须为方阵、对称、二值、无自环。
- CSR 节点数必须与所选档案完全相同，否则拒绝，绝不裁剪或猜测节点映射。
- 选择错误数据集时显示上传节点数和可信档案节点数。
- 完整图继续执行现有维度、类型、边范围、重复边和内存限制校验。

## 影响范围

- 修改上传页面、检测输入加载和针对该路径的测试。
- 不修改共享检测器结构、训练语料、阈值、攻击生成、防御模型训练或准确率报告。
- 不自动识别数据集，不根据节点数猜测来源，不自动裁剪图。

## 验证

- 选择数据集后，完整 NPZ/PT 继续可检测。
- CSR-NPZ 选择正确档案后能补充属性并检测。
- CSR-NPZ 未选择或节点数不匹配时返回明确错误。
- 页面不再出现“节点属性类型”，导航显示“鲁棒防御模型”。
- 完整测试集通过。
